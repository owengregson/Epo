# Timing and identity input QC — 2026-09-21

This audit exercised local code, seeded simulations, fake pages and in-memory
stores. It did not perform Instagram actions. The measurements establish
bounded variation and interaction correctness; they do not establish that
Instagram cannot identify the app or that the generated behavior matches a
measured population of human users.

The main cadence bug was in `SessionPlanner.nextActionGapMs`: dividing the
entire sampled gap by recent-action excitation, then applying the safety floor,
mapped many distinct samples to exactly 45 seconds. Excitation now compresses
only the time above the floor. Cold-session draws are unchanged, and busy
sessions retain variation without lowering the floor or increasing the cap.

`node scripts/timing-qc.mjs` compares the previous formula with the current
implementation using the actual default settings, seed `20260921`, and 50,000
draws per scenario. Each busy scenario places the stated number of recent
actions at the sampling instant to stress the compression path.

All draws remain at least 45 seconds and at most 480 seconds. The small
remaining floor mass comes from the existing bounded sampler's fallback after
four rejected draws. The existing 30-day simulation still passes its volume,
circadian, gap-variation and rolling-hour-cap assertions.

The production rate governor and standalone prune engine also accepted equal
delay bounds with zero jitter, creating a fixed interval. The shared
`actionGap` policy now samples from `[base, 1.45 × base]` only in that degenerate
positive case. It never accelerates an action relative to the configured
interval. The band uses the existing `NOISE.BEAT_MAX_FACTOR`; no new tuning
constant was introduced. Existing variable ranges and zero-duration simulation
policies retain their exact draws and RNG consumption. Prune applies its
one-third multiplier after sampling. For a 60-second setting the same probe
produced 22,747 distinct millisecond delays across 50,000 draws, all within
60–87 seconds, compared with one distinct delay previously.

Default follower-dialog scrolling now draws a fresh 1.4–2.9-second pause from
the existing sub-cadence band instead of repeating a fixed 2-second pause.
Explicit scan bounds retain their existing policy. Profile landing and failed
identity-resolution retries use fresh bounded pauses too. URL readiness polls,
mutation verification deadlines, rate limits, local UI polls and watchdogs
retain their correctness semantics. Existing sweep factors are durable, and
direct list walks already vary both their page pauses and their 5–10-page rest
strides.

Identity resolution no longer invokes the synthetic `clickProfileLinkScript`.
The foundation and every capture, inspect, probe and live-test resolver supply
`createTabInteractor(tab)` before the graph is constructed. The resolver locates
the link in-page, then uses the same guarded native input path as the Actor.
A caller with no input dependency skips that fallback and proceeds to the API.
An abort during locate or navigation settle prevents further API work; a broken
input transport or stalled tab stops resolution. A stale/covered control can fall through to
the API without forcing a click. The old synthetic escape remains declared for
surface-document compatibility and fixtures, with no runtime call sites.
This retires the pre-graph identity exception described in ADRs 0305 and 0805.

The final listed Jest run passed 60 suites and 642 tests. Earlier focused runs
also covered follower acquisition, follower/own-list reading and the profile
landing integration. The tests exercise bounded draws, distinct-gap counts,
existing distribution compatibility, interruption during retry, native
identity click-through, transport failure, and preservation of the sampled
deadline across pause/resume. No live-account validation is included here.

The renderer canary also now measures frame throughput using actual monotonic
elapsed time. A nonzero rAF count is insufficient: one callback delivered after
one second reports 1fps and fails the named 10fps engineering guardrail. A
nominal 500ms window therefore cannot make a late frame look healthy. Both the
frame and timer completion paths cancel outstanding callbacks, and callbacks
delivered after completion cannot restart the loop. A tiny injected window
still allows one ordinarily scheduled frame before its backstop. The compiled
script is scoped to an IIFE and leaves no `window.__epoPage` marker.

`npx jest tests/adapter/renderer-canary.test.ts --runInBand --silent` passed 13
focused tests: 62.5fps throughput, 1fps throttling, zero frames, a 1ms injected
window, a late timer's real elapsed time, callback retirement, malformed samples,
and the compiled injection's local scope. This guardrail diagnoses renderer
responsiveness; it is not a claim about human interaction cadence.
