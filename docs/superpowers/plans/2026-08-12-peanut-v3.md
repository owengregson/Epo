# Peanut v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild Peanut as a reliable, safe, observable Instagram growth engine whose foundation is a local event-sourced knowledge graph of an Instagram neighborhood, with an embedded (visible) Instagram tab and request-minimal interaction.

**Architecture:** Single Electron app. Main process owns all logic + a SQLite (`better-sqlite3`) knowledge store reached only through one `KnowledgeStore` module. Instagram runs as a visible `WebContentsView` tab driven via a single versioned Instagram Adapter (Reader = API-intercept, Actor = the only DOM-touching code, Sentinel = block detection). Governors enforce durable daily action caps and a global request budget. Build proceeds verified-foundation-first: Phase 1 proves the store, governors, and adapter against **live Instagram** before any churn logic is trusted.

**Tech Stack:** TypeScript, Electron 31, `better-sqlite3` + `@electron/rebuild`, esbuild, Preact (renderer), Jest + ts-jest (tests). No Puppeteer.

## Global Constraints

- **Node ≥ 18.** Electron 31. TypeScript `strict: true` (see `tsconfig.json`).
- **The `KnowledgeStore` module is the ONLY file permitted to import `better-sqlite3` or contain SQL.** Every other module reads/writes the graph exclusively through its typed API. This is enforced by review; a task adds an ESLint `no-restricted-imports` rule for `better-sqlite3` outside `src/store/`.
- **Account identity is the numeric Instagram `pk` (string), never the username.** Usernames are attributes with history.
- **No blind overwrites of graph state.** All learned facts enter through `KnowledgeStore.observe(...)`; current state is a projection of appended observations.
- **No silent `catch {}`.** Every caught error is logged through the structured logger and surfaced; parsing that legitimately may miss uses an explicit typed "no match" result, not a swallowed throw.
- **Hard daily action ceiling is enforced in code from the durable `action_ledger`, default `50`; default operating rate `25`.** The UI cannot exceed the ceiling.
- **All Instagram reads consult the knowledge graph first;** a network request is issued only when a needed fact is missing or staler than the decision's freshness requirement.
- **`better-sqlite3` is a native module:** it must be built for system Node to run Jest, and rebuilt for the Electron ABI (`@electron/rebuild`) to run the app. `npm test` uses the Node build; `npm start`/`npm run dev` run `electron-rebuild` first. Never assume one build serves both.
- **Ratio is `r = following ÷ followers`.** Eligible band `0.90–1.50`, peak plateau `1.0–1.2`, hard-exclude `r > 3.0` or `r < 0.5`. All bounds are Settings values, not literals in logic.
- Commit after every green step. Conventional-commit messages.

type Level = 'debug' | 'info' | 'warn' | 'error';
const RANK: Record<Level, number> = { debug: 10, info: 20, warn: 30, error: 40 };
let level: Level = 'info';
let sink: ((l: Level, m: string, meta?: unknown) => void) | null = null;
export const setLevel = (l: Level) => { level = l; };
export const setSink = (fn: typeof sink) => { sink = fn; };
const emit = (l: Level, m: string, meta?: unknown) => {
  if (RANK[l] < RANK[level]) return;
  sink?.(l, m, meta);
  const line = meta ? `${l.toUpperCase()} ${m} ${JSON.stringify(meta)}` : `${l.toUpperCase()} ${m}`;
  (l === 'error' ? console.error : console.log)(line);
};
export const debug = (m: string, meta?: unknown) => emit('debug', m, meta);
export const info = (m: string, meta?: unknown) => emit('info', m, meta);
export const warn = (m: string, meta?: unknown) => emit('warn', m, meta);
export const error = (m: string, meta?: unknown) => emit('error', m, meta);
```

export type Source =
  | 'followers-list' | 'show-many' | 'profile' | 'activity-feed' | 'search' | 'action';
export const SOURCE_CONFIDENCE: Record<Source, number> = {
  'followers-list': 40, search: 40, 'activity-feed': 60, 'show-many': 80, profile: 90, action: 100,
};
export type EnrichmentLevel = 'stub' | 'listed' | 'profiled';
export interface AccountFields {
  username?: string; followers?: number; following?: number;
  isPrivate?: boolean; isVerified?: boolean; activitySignal?: number;
}
export interface Observation {
  accountPk: string; observedAt: number; source: Source; fields: AccountFields;
}
export interface AccountState {
  pk: string; username?: string; enrichment: EnrichmentLevel;
  followers?: number; following?: number; ratio?: number;
  isPrivate?: boolean; isVerified?: boolean; activitySignal?: number;
  statsObservedAt?: number; statsSource?: Source; firstSeenAt: number; lastSeenAt: number;
}
export type EdgeType = 'follows';
export interface Edge {
  srcPk: string; dstPk: string; type: EdgeType;
  firstSeenAt: number; lastConfirmedAt: number; status: 'active' | 'removed';
}
export const ratioOf = (followers?: number, following?: number): number | undefined =>
  followers && followers > 0 && following !== undefined ? following / followers : undefined;
```

**Interfaces:**

- Produces:
  - `interface Clock { now(): number }`; `SystemClock`; `FakeClock(start)` with `set(t)`/`advance(ms)`.
  - `class RateGovernor(store, clock, cfg)` where `cfg = { dailyHardCeiling, dailyOperatingRate, minDelayMs, maxDelayMs, jitterPercent, activeHoursStart, activeHoursEnd }`:
    - `remainingToday(): number` (operating rate − `actionCountSince(startOfTodayLocal)`; never below 0).
    - `atHardCeiling(): boolean` (count ≥ `dailyHardCeiling`).
    - `withinActiveHours(): boolean`.
    - `nextDelayMs(rng = Math.random): number` (base in [min,max], ± jitter).
  - `class RequestBudget(store, clock, cfg)` where `cfg = { maxRequestsPerWindow, windowMs }`: `canSpend(): boolean`; `spend(): void` (records a request); `remaining(): number`.

## PHASE 2 — Churn Core (work-packages; detail after Phase 1 gate)

Expanded into bite-sized tasks once Task E's field notes are final. Packages, each an independently testable deliverable with unit tests over the KnowledgeStore + fixtures:

- **P2-A Scorer** (`src/engine/scorer.ts`) — pure ratio sweet-spot scoring: full score on `[peakLow,peakHigh]`, decay to band edges `[0.90,1.50]`, heavy penalty in soft zone, exclude past `[hardLow,hardHigh]`; plus composite weighting (private boost, size-fit, activity). Fully unit-testable now against §3.2 — **can start in parallel with Phase 1** if desired.
- **P2-B Scanner** (`src/engine/scanner.ts`) — poach loop: page target followers via Reader+cursor (budgeted), `observe()` each, apply cheap pre-filters, select the top slice needing `profiled` enrichment, fetch only those profiles.
- **P2-C Follow-back Watcher** (`src/engine/followback-watcher.ts`) — batched `friendships/show_many` on a cadence (≤ `SHOW_MANY_MAX_BATCH` per call), activity-feed piggyback, incremental head-read backstop; updates `follow_records` + edges. **Never full-list diff.**
- **P2-D Churn Scheduler** (`src/engine/churn-scheduler.ts`) — the §3.4 state machine over `follow_records`, driven by an interruptible loop (`AbortSignal`), gated by governors; requeues on failure with backoff; **never drops due items** (regression test against the old bug).
- **P2-E Phase 2 gate** — live: seed target → qualify → follow → detect real follow-back → hold → unfollow, all within budget.
